How to walk

  1. Four columns, three surfaces. Web = the Next.js site at desktop width (localhost:3000 or the deployed site). iPhone = the Expo app on your iPhone 16. Android emu = the same Expo app on the Android Studio emulator (a Pixel image with Play Store) — the daily Android column. Android real = a physical or browser-streamed real device (BrowserStack App Live / a borrowed phone) running the build installed from the Play internal track — done once, at the end.
  2. The Expo web preview (localhost:8081) never earns an Android tick. It is react-native-web: no hardware back button, no soft keyboard, no expo-sqlite, no share sheet, no edge-to-edge. Use it to look, not to sign.
  3. Android real is required only on NATIVE rows — the ones that touch the OS (files and the share sheet, the keyboard, hardware Back, storage across a restart, WebView, SVG, fonts, safe areas). A cheap Samsung or Xiaomi differs from the emulator exactly there. The other real-device cells are optional (shown as opt); tick them if you pass through. Focus an Android column to see each row's On Android watch line.
  4. Walk one surface at a time. In the Walk tab choose Focus: iPhone (etc.). Each row gets inline P / F / N/A buttons. In the drawer: P pass, F fail, N n/a, R re-walk, → next row, Esc close.
  5. A fail needs words. Say what you saw. Then press Raise amendment — it opens pre-filled. One amendment can cover several surfaces.
  6. Walk → fix → re-walk, never fix → fix. The map's hand-off records four walks lost to fixes made without looking. When an amendment is marked fixed-awaiting-rewalk its surfaces go amber; only a fresh pass turns them green. A fix to shared code (packages/shared) or the API re-opens all surfaces for that feature.
  7. Order. ① Walk everything in Expo Go + emulator + web (fast reload, most fixes land here). ② Build the development build with EAS for both platforms and re-walk only NATIVE rows + everything amber. ③ Build the store candidates (TestFlight + Play internal), install from the stores, run the Release-switch checklist and the Android-real column. If step ③ needs a code change, it was not a switch — record it as an amendment and say why.
  8. Claude's half. When the API is not reachable from a Cowork session, Claude edits data/testing/walk_state.json directly (same shape this page exports) and records amendments there with the commit hash.
