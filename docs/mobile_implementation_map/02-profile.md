# Teaching Profile family — TeachingProfile.jsx · wheels.jsx · shared budget/readiness/format (the bar's "Add" destination; Track D step 5c in flight)

Scope note. On the web this family is reached by three doors, all rendering ONE component
(`TeachingProfile`, page.jsx:1305-1313): (1) the bottom bar's **Add** → `ProfilePortal` window
(change mood) → `onProfilePortal(kind)` (page.jsx:1007-1013) → TeachingProfile in **manage mode**
with `portalIntent`; (2) the check-mood window after the tour / after a subject-stage is added
(same `onProfilePortal`, with `portalScope`); (3) Year Plan's budget pencil → `onEditYearBudget`
(page.jsx:1034-1044) → `portalIntent="budget"` with an `exact` scope; (4) Settings › Teaching
profile → the bare accordion (`profileViaSettings`, `onBack=null`). Every exit of a portal visit
goes back through `goPortalHome` (page.jsx:1045-1051), which restores the tab AND the window.
On the phone, none of these doors exists yet: `BottomNav` renders **Add** with `onAdd={() => {}}`
(mobile/app/(app)/_layout.jsx:44), YearPlan accepts `onEditBudget` but lessons.jsx does not pass
it (lessons.jsx:602), and Settings is step 6. What HAS landed for 5c: `packages/shared/src/budget.js`
(reader + normaliser + writer), `web/app/lib/budget.js` (the web re-export), and the
`tp_val_*` / `tp_weeks` / `tp_estimate_sub` / `fr_q` / `fr_foot` / `fr_cta` / `fr_link` measures in
`mobile/theme/web.js:622-651` — with NO mobile consumer of any of them yet.
