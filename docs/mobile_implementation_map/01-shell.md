# App shell (page.jsx + layout.jsx + GuidedTour + ProfilePortal + MeyyMark + shared-setup)

Snapshot note: `web/app/lib/` in the snapshot holds only `budget.js`, `shared-setup.js`, `useSupportedGrades.js`. The thin wrappers page.jsx imports (`./lib/format`, `./lib/verify`, `./lib/sectionState`, `./lib/sectionHistory`, `./lib/auth`, `./ask-aruvi/bank`) are absent from the upload; per CLAUDE.md §5 they are one-line re-exports of `@aruvi/shared/*` after `import "./shared-setup"`. Line refs below for those helpers point at the shared package, which is the real logic on both surfaces.

## Open questions for the founder

1. **Paywall on the phone without a Subscribe flow.** The web's paywall offers "Subscribe" (SubscribeFlow) + "Not now"; the phone's sheet offers only "Close" under a fixed title "Your free chapters are used up" that misdescribes the "different subject" and "subscription ended" 402s. Should the phone (a) mirror the web's kicker rule with the server sentence and a single "Not now", and (b) say anything about HOW to subscribe (support@meyy.in? nothing?) while purchases are manual grants?
2. **Lapsed on the phone.** Web hides My Classes and Add and forces My Lessons for a lapsed subscription. The phone has no entitlement derivation. Confirm the same rules apply on the phone during the beta (enforcement is OFF on the deployed API, so today no teacher is ever lapsed) — i.e. port now and let the server flag drive it, or leave until enforcement is turned on.
3. **First-run gate location.** page.jsx decides FirstRun vs shell after ONE `/readiness` read and the `firstGenNeeded` triple read. On the phone, should the gate live in `app/index.jsx` (before the shell mounts, like the login redirect) or inside `(app)/_layout.jsx` (so a mid-session profile wipe re-routes)? The web's behaviour is the latter (it re-evaluates whenever `ready` flips).
4. **Display name on the bar.** Web shows the captured first name; phone shows the raw mobile number. Is the number-on-the-bar acceptable until Settings › Personal profile exists on the phone, or should the account fetch (row 29) land first so both surfaces greet her by name?
5. **`html.app-shell` equivalents already differ by nature; nothing to ask.** But note the phone renders `<Bar>` per route rather than one bar in the layout — the web has "one bar, one shell". Moving `<Bar>` into `(app)/_layout.jsx` would guarantee it never disappears (the 2026-09-14 "login and wheel disappear" bug class) and give Ask Meyy/portal a fixed anchor. Product-neutral, but it changes every route file — worth a yes/no.
